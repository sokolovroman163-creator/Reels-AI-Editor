## Материалы для функциональной проверки

Использовать 3–5 коротких собственных тестовых роликов, содержащих явно отличимые
кадры и русскую речь. Для первичной технической проверки пригодны синтетические
ролики с цветными сценами и счётчиком времени; они проверяют trim, порядок и экспорт,
но не качество визуального выбора Beauty. Не публиковать клиентские ролики в GitHub.

Сохранить отдельную копию проекта до начала проверки. Установить локальный Whisper
addon штатным Addon Manager. Указать название/версию установленного addon в отчёте.

## Отказоустойчивость и безопасность

Автоматические тесты должны проверять HTTP 400/401/402/403/429/5xx, timeout,
повреждённый JSON, ограниченный retry, явное unsupported-tools и недоступную модель.
Использовать локальный тестовый сервер и фиктивный ключ `pza_TEST_KEY`.
Не отправлять фиктивный ключ в настоящий Polza в автоматических тестах.

Проверить agent limits (18 шагов по умолчанию и три одинаковые ошибки), отказ
неизвестных операций, ошибку в конце пакета до первой мутации, восстановление
snapshot и отмену во время ожидания ответа. Обычные MCP tests должны оставаться зелёными.

На Android проверить Keystore: ciphertext в приватных preferences, отдельный
AES-GCM alias, отсутствие plaintext в QSettings/проекте/backup/Logcat. Не выводить
содержимое реального ключа даже в протокол проверки. Отдельно проверить, что удалён
и ciphertext, и alias. Подпись APK проверять через `apksigner verify`.
